# Локальный выпуск расширений

Пакеты собираются на компьютере разработчика. GitHub Releases хранит готовые
подписанные `.anmx`, VPS только зеркалирует их. GitHub Actions и GitHub Pages
для этого пути не нужны; push не запускает платную облачную сборку.

## Подготовка

Нужны Rust/Cargo, target `wasm32-wasip2`, PowerShell 7 и GitHub CLI (`gh auth login`
для публикации с правом записи в репозиторий).

```powershell
rustup target add wasm32-wasip2
```

Используйте существующий приватный seed, соответствующий `repository-key.json`:
переменная `ANMX_SIGNING_KEY`, файл `~/.animex/signing-key.private` или параметр
`-SigningKeyFile <внешний-путь>`. Скрипт проверяет публичный ключ до сборки модулей,
не выводит seed и восстанавливает прежнее окружение при завершении/ошибке.
Новый ключ нельзя подставлять вместо существующего: установленным приложениям
потребуется явно доверить его заново.

## Проверка изменений и выпуск

После каждого повышения версии расширения публикуйте подписанный выпуск в
GitHub Releases. AniMex получает обновления через каталог Latest.

1. Измените код и увеличьте `version` в `module.json` изменённых модулей.
2. Соберите и проверьте локально:

   ```powershell
   pwsh -NoProfile -File scripts/release.ps1
   ```

   Скрипт тестирует SDK и все модули из `modules.json`, собирает WASM,
   подписывает пакеты и два каталога. Каждый запуск создаёт новую папку
   `dist-releases/`; старые файлы в каталог не попадают. Без ключа доступна
   только проверка WASM: `pwsh -File scripts/build.ps1 -Test -Unsigned`.

3. Закоммитьте и отправьте исходники в `main`, затем:

   ```powershell
   pwsh -NoProfile -File scripts/release.ps1 -Publish
   ```

   Публикация требует чистого рабочего дерева и совпадения HEAD с GitHub main.
   Скрипт повторяет сборку и проверки, создаёт draft с тегом
   `extensions-<unix-time>-<commit>`, загружает все assets и только затем
   публикует его как Latest. Ошибка загрузки оставляет draft и предыдущий
   Latest. Каталог проверяется на повышение revision и изменение пакета без
   повышения версии. Не редактируйте и не перезаписывайте готовые assets.

4. Проверьте, что `releases/latest/download/index.json` содержит новую версию
   расширения и пакет скачивается по адресу из индекса.

Если менялась версия одного расширения, можно передать
`-ModuleId <id>` вместе с `-Publish`. Скрипт пересоберёт его, проверит и
переиспользует прежние пакеты остальных расширений.

## Прямое скачивание из GitHub

После первого опубликованного выпуска подключите в AniMex:

**https://github.com/Senkai350/animex-extensions/releases/latest/download/repo.json**

`repo.json` указывает на стабильный `latest/download/index.json`, поэтому
обновление каталога находит следующий выпуск. Подписанный индекс содержит
адреса пакетов с конкретным тегом: смена Latest не подменяет старые пакеты.
Не удаляйте старые releases, пока ими могут пользоваться клиенты.
Для публичного репозитория приложению не нужен GitHub token.

Идентификатор и публичный ключ GitHub/VPS-каталогов совпадают: это зеркала,
в приложении используйте один адрес. Для смены уже добавленного адреса удалите
старое подключение репозитория и добавьте GitHub URL с проверкой прежнего ключа.
Обычное открытие страницы модулей читает сохранённый каталог; кнопка обновления
репозитория загружает актуальный индекс. Установленные плагины обновляются
отдельным действием пользователя.

## Зеркало VPS

Выпуск также содержит `repo-vps.json` и `index-vps.json` с адресами
`https://senkai.fun/extensions/`. Пакеты `.anmx` общие для обоих каталогов.
Один раз установите обновлённый `deploy/animex-extensions-sync.py` на VPS
по [инструкции](../deploy/README.md). Таймер каждые две минуты скачивает Latest,
проверяет размеры, хеши, подписи, ключ и revision, затем атомарно переключает
каталог. При ошибке остаётся предыдущий выпуск. Ничего не компилируется.

Старый VPS-скрипт, который читает Actions artifacts, нужно заменить:
публикация GitHub Release сама по себе не обновляет старое зеркало.

## Проверка скриптов выпуска

После `cargo build --locked --manifest-path vendor/sdk/Cargo.toml -p anmx`:

```powershell
pwsh -NoProfile -File scripts/tests/release.test.ps1
python deploy/test_sync.py
```

PowerShell-тест использует изолированные фикстуры, настоящие подписи и подменённые
Git/GitHub/Cargo: проверяет порядок draft → Latest, отказ при незакоммиченных
или неопубликованных исходниках, изменении во время сборки, ошибке загрузки,
неверном ключе, прежней версии с новыми байтами и откате версии/revision.
Он ничего не загружает в GitHub. Python-тестам нужны `cryptography` и OpenSSL
(`ANIMEX_OPENSSL` позволяет указать путь на Windows); тест symlink пропускается,
если Windows не предоставляет право создания ссылок.
